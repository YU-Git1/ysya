# 压缩鸭本地压缩策略

## 当前实现

当前版本使用浏览器内置解码器、Canvas 和本地自适应编码，不依赖网络，也不调用 AI。

- JPG/JPEG：生成多个质量候选（96%、90%、84%、78%、72%、66%、58%），对每个候选做小尺寸像素采样比较；在视觉相似度达到阈值的候选中选择体积最小的文件。
- WebP：采用同样的候选质量和像素误差选择策略。
- PNG：使用无损 PNG 编码，不降低像素质量；如果输入本身已经很小，结果可能不会变小，这是无损格式的正常结果。
- 原格式：输入 JPG、PNG、WebP 时分别使用对应编码器；选择转换格式时使用用户指定的 MIME 类型。
- 暂停：编码候选之间检查暂停状态，不阻塞页面主线程的任务控制。

## 为什么不用固定质量

同一个质量数字在不同图片上的体积和观感差异很大。纯固定质量会让简单图片浪费体积，也可能让纹理复杂的图片出现明显损失。候选编码加视觉阈值可以根据图片内容自动选择更合适的质量档位。

## 当前边界

浏览器 Canvas 的编码器不是专业的 MozJPEG、pngquant、libavif 或 GIF 优化器，因此当前实现适合作为本地 MVP 的可靠基线，不能宣称已经达到这些原生编码器的极限压缩率。EXIF、ICC、XMP 等元数据不会被完整保留，JPG 透明通道会以白色背景输出。

## 下一步的专业编码层

当要扩展到更多格式时，使用 WebAssembly 编码器并通过 Web Worker 执行：

| 格式 | 推荐本地编码器 | 处理策略 |
| --- | --- | --- |
| JPG/JPEG | MozJPEG | 感知量化、渐进式 JPEG、去除无用元数据 |
| PNG | pngquant + oxipng | 颜色量化后再无损重排；有透明通道时保留 alpha |
| WebP | libwebp | 有损/无损双路径，按内容选择 |
| AVIF | libavif + libaom | 高压缩率，提供速度档位和兼容性提示 |
| GIF/APNG | gifsicle / oxipng | 调色板优化、帧差分、重复帧删除 |
| TIFF | libtiff | 保留通道和位深，默认无损压缩 |
| HEIC | libheif | 解码后明确提示输出格式，避免伪装为原格式 |

## 画质保护原则

1. 先识别颜色空间、透明通道、位深和动画属性。
2. 无损格式默认不丢像素；有损格式使用感知指标和人工可解释的质量档位。
3. 不只看 SSIM：同时检查边缘、文字、细线和透明边缘，避免平均指标掩盖局部损失。
4. 结果页显示原始大小、输出大小、节省比例、输出格式和是否保留元数据。
5. 用户可以选择“体积优先、平衡、画质优先”，而不是把算法决策完全隐藏。
6. 所有编码放进 Worker；大图分批处理，避免手机页面卡死。

## 格式支持路线

第一阶段先稳定 JPG、PNG、WebP 的本地高质量压缩。第二阶段引入 AVIF、GIF/APNG、TIFF、HEIC 的 WASM 编码器，并增加文件夹输入、ZIP/文件夹导出和断网 PWA 缓存。Tauri 桌面版可以在之后复用同一套任务模型，替换为原生编码器以获得更完整的格式覆盖和文件系统权限。
